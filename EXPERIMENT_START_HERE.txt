OPERATION
- Only OAK-D S2 input in production. Automatic camera connection/reconnection 24/7.
- Production counting: weekdays 05:00 inclusive to 17:05 exclusive, Brisbane time.
- Pause keeps the camera and recording connected. Resume re-enables scheduled counting.
  A manual pause expires on the next Brisbane date; counting resumes in the next shift.
- Default start/end are 78%/22% of frame height for bottom-to-top travel, reversed
  for top-to-bottom. They are adjustable now. They count while hidden.
  Adjust lines temporarily reveals them; Lock lines restores previous visibility.
- Default middle is a diagonal joining the adjustable horizontal start and end lines across the frame.
  Admin Settings > COUNTING selects Zigzag, mirrored Zigzag, or Three horizontal lines.
  In horizontal mode only, the middle position is adjustable 26–74%.
  Changing mode clears motion history while retaining accepted counts. All three lines
  use tyre centres. Avoid changing geometry while tyres cross it.
- One accepted count per track, with conservative short-gap ID continuation.
  Middle/end recover tyres missed at preceding lines. Ambiguous IDs are not merged.
- Passenger boxes green; SUV/4x4 blue. Existing model weights and reporting logic retained.
- Best hour, best day, hourly/per-minute average and flow displayed.
- A new daily best hour triggers a banner and cheering/applause once that hour.
  No celebration in the first hour until a completed-hour benchmark exists.
  Mute setting is independent of foreign alarms. Alarms take priority.
- Included sound is a generic public-domain crowd, NOT a verified Australian crowd/chant.
- Foreign detection starts OFF each launch; existing starter model is not validated
  as a reliable general foreign-object detector. Enable in Admin and reconnect to apply.
- OAK runs camera, tyre NN and H264 compression. PC retains decoding, ByteTrack,
  count logic, dashboard and reports. No extra default neural workload was added.

ADMIN SETTINGS > COUNT LOGIC TEST
1. Run simulated logic checks: no camera needed; does not modify production counts.
2. Main dashboard > VIDEO TEST: choose/upload an existing recording; no OAK is required.
   Start video test temporarily stops the OAK worker and pauses automatic connection
   retries. It works at any time, including outside production hours.
   Enter an optional full-video hand count, select the annotation mode, then Start.
   The options window closes and analysed video frames appear directly in the large
   dashboard display. The progress bar and test header show percent complete, unique
   test total and processing FPS. Preview updates up to eight times per second;
   this is analysis-speed viewing, not a guarantee of real-time playback.
   Use Stop test below the display to stop safely. Upload video test/Test options
   reopen the options and results. TEST COMPLETE and 100% identify a finished run.
   Stop finalises the partial output; hand-count comparison is disabled for an early stop.
   Open annotated test video and Open test results folder provide the output.
   Return to live OAK mode resumes automatic camera connection.
   Runs CPU inference in a separate process with the same three-line counter.
   All three geometries receive the SAME detections/tracks for a fair software comparison.
   mode_comparison.json reports unique totals, crossings and recoveries for each geometry.
   Results: reports/count_logic_tests/replay_.../annotated_test.mp4,
   crossings.csv, test_summary.json and replay_log.txt.
   The OAK worker stops before CPU replay starts, so both do not compete for PC resources.
3. Live shadow test: start/reset, hand-count the exact same interval, stop, enter your hand
   count, export test JSON. Test counters are separate; production continues on schedule.
   Tests can run outside production hours without adding production counts.
   A shadow test cannot prove accuracy without a matching hand count.

BEFORE USING ON THE YARD PC
Build and test on the development PC first. Keep the previous working application.
Back up and preserve the current data and reports folders (including private configuration).
Do not replace a working production database with this package's test data: none is included.
Stop the old application before connecting the new one to the same OAK.
A physical camera run is still required for streaming, performance, sound-device playback
and real-world count accuracy. Long occlusions, tracker resets and camera reconnects can
still create missed/duplicate tyre identities; three lines do not guarantee perfect counts.

Offline command from source (after dependencies are installed):
py offline_replay.py --video "C:\path\recording.mp4" --output "C:\path\test_results" --hand-count 100
Packaged equivalent:
TyreTrack.exe --replay-test --video "C:\path\recording.mp4" --output "C:\path\test_results" --hand-count 100

The pre-existing admin PIN/password mechanisms remain in this experimental source.

ZIGZAG GEOMETRY
For each segment from (xL,yL) to (xR,yR), m=(yR-yL)/(xR-xL).
Signed perpendicular distance is d=(y-yL-m*(x-xL))/sqrt(1+m*m).
A forward crossing changes the stable approach sign to the departure sign.
The interpolated intersection must lie on the visible segment, and longitudinal
movement must agree with belt direction. A perpendicular pixel margin rejects jitter.
Horizontal start/end remain active even when hidden. The diagonal is visible.
No extra OAK neural workload is added. Geometry runs on the PC after tracking.

Compare modes offline from source:
py offline_replay.py --video "C:\path\recording.mp4" --output "C:\path\zigzag_test" --compare-modes --mode zigzag --hand-count 100
The test tool exports mode_comparison.json plus the selected mode's annotated video.
Use matching hand counts and review the annotated footage: equal totals can conceal
one missed tyre and one duplicate. A diagonal cannot identify a completely hidden tyre.

ADJUSTABLE CONNECTED ZIGZAG
Click Adjust lines below the display. Drag the TOP or BOTTOM horizontal line's
central handle up/down; the diagonal follows both ends automatically. Click Lock lines
when done. Sliders in Admin > Counting offer the same adjustment and save positions.
Top/bottom are restricted to 5–95% of frame height, with at least 12% separation.
The horizontal middle line is kept inside those bounds when comparing modes.
Live OAK and uploaded tests use the same requested geometry. Test runs accept changes
between frames and record them in geometry_changes in the exported JSON.
Changing geometry clears motion references but keeps accepted counts. Set positions
before the measured run whenever possible: moving lines can temporarily miss crossings.
This remains an experimental counting strategy, not proof of better overlap detection.

LINE LENGTH / CONVEYOR ALIGNMENT
Click Adjust lines. Drag the L/R handles horizontally to shorten or shift all three
segments over the conveyor. The diagonal stays attached to the horizontal ends.
Admin > Counting also has saved Conveyor left edge / Conveyor right edge sliders.
The selected span applies to live counting, uploaded video tests and comparisons.
Only crossings on the selected segments are accepted. Geometry changes clear motion
references while retaining accepted counts. Set and lock the geometry before measuring.
